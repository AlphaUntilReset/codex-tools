# 功能与状态说明

Codex Tools 是独立的 Windows 桌面配套工具。桌宠画面来自你自己的透明 PNG，任务信息来自选择的本地连接，用量信息来自独立的套餐查询。显示和操作能力不依赖作者的角色美术。

## 桌宠与任务面板

| 功能 | 使用方式与边界 |
| --- | --- |
| 高清透明桌宠 | 一张 PNG 即可显示；可拖动、缩放、置顶，支持鼠标穿透与悬停淡化。动画需自备帧。 |
| 自然动作 | 待机、工作片段及可选生活动作之间切换；减少动态、暂停动画等选项可在设置中调整。 |
| 16 方向跟随 | 自备完整的 16 张方向图，开启鼠标跟随；没有方向图时使用待机首帧。 |
| 显示控制 | 托盘显隐与位置重置；可配置 `Ctrl+Alt+P`，也可选择随 Codex 显隐。 |
| 任务状态卡片 | 展示工作中、等待输入、受阻、完成未读等状态；可折叠，点击任务尝试打开对应 Codex 页面。 |
| 新任务草稿 | 在小窗口写草稿，再交给 Codex 输入页；仍需在 Codex 选择项目并确认发送。 |
| 请求提示 | 可选 hooks 提供审批或输入请求提示；是否允许操作仍由 Codex 的审批机制决定。 |
| 登录自启 | 用户明确开启时配置；不会因为准备图片或执行代码测试而自动添加。 |
| 退出诊断 | 独立记录器保留实际退出证据；日志只在本机，不随公开源码或程序包分发。 |

任务连接默认关闭。需要真实任务状态时，在托盘设置中选择 `codex-local`；`demo` 使用明确标记的演示事件。连接中断时显示断开或待确认，不把旧的工作状态持续当作实时事实。没有本地连接或没有任务数据时，桌宠本身仍可显示和交互。

任务的基础颜色是：工作中为绿色 `#39836e`，等待输入与完成未读为橙色 `#b48136`，受阻为红色 `#b65f62`，完成或停止为灰绿色 `#84948a`，待确认则为灰色 `#929991`。明确的待处理原因可以覆盖为橙色提示。任务颜色和下面的用量颜色是两个独立指标。

## Codex 套餐用量（coding plan 余额）

面板中的“余额”指**当前所读取限额窗口的剩余比例**，不是现金余额、API 账户余额或剩余 token 数。当前实现读取用量响应的 `rate_limit.primary_window`，并计算：

```text
剩余百分比 = round(clamp(100 - used_percent, 0, 100))
```

它不会把所有窗口、所有模型或其他工作区的限制合并成一个总余额。窗口长度和重置时间优先使用响应值；没有窗口长度时，代码采用 7 天作为比较基准。界面可显示剩余百分比、距重置时间、重置时刻，以及最近一次成功更新时间。

### 颜色如何判断

颜色比较“时间走到了哪里”和“额度用了多少”。令 `e` 为当前窗口已过去的比例、`u` 为已用百分比，计算：

```text
进度差 Δ = 100 × e - u
Δ >= 15 个百分点：绿色 #39836e
Δ <= -15 个百分点：红色 #b65f62
其余：默认文字颜色
```

例如，同一个窗口已经过去一半：

| 已用 | 剩余显示 | 进度差 | 颜色含义 |
| --- | --- | --- | --- |
| 30% | 70% | +20 个百分点 | 绿色：用量低于均匀分配的进度 |
| 50% | 50% | 0 | 默认色：接近均匀进度 |
| 70% | 30% | -20 个百分点 | 红色：用量高于均匀分配的进度 |

所以绿色不固定代表“剩余超过某个比例”，红色也不等于“马上用完”。这是简单的进度比较，不预测未来消耗速度。服务端明确报告额度受限时，新鲜数据直接显示红色；缺少必要数据或旧数据不继续标色。

### 刷新和错误状态

- 启动后约 2 秒开始查询；正常空闲时约 10 分钟一次，检测到工作中的任务时约 1 分钟一次。
- 网络、登录或响应失败时约 1 分钟重试；检测到本机登录文件变化后重新查询。慢请求不会叠加成多个并发查询。
- 20 分钟未成功更新的数据标记“待更新”并取消额度颜色。旧值最多保留 2 小时；到达重置时刻会等待新数据，不自行把余额改成 100%。
- 未发现登录时显示“未登录”，凭据失效时显示“登录过期”；网络或响应结构异常时显示暂不可用。短暂网络错误可保留仍有效的上次结果。

套餐查询独立于任务连接模式。即使任务连接关闭，程序仍会尝试从本机 Codex 登录文件读取查询所需的凭据，并向用量端点发送只读请求；凭据不随项目分发，也不写入项目配置。当前程序不代替用户登录，不刷新登录令牌或改写登录文件。此查询依赖服务端响应结构，结构变化可能导致暂不可用。更完整的数据边界见 [PRIVACY.md](../PRIVACY.md)。

## 背景美化

选择一张主背景 PNG 和两张侧栏 JPEG 后，在本机生成带图片的 CSS。伴随进程通过仅监听本机地址的调试连接加载背景；图片没有上传步骤。登录入口、桌面快捷方式、禁用与恢复功能有独立校验和备份。

背景依赖当前 Codex 界面的结构和启动参数。客户端重启后应确认实际状态为 `applied`；进程存在或源码更新完成都不能代替背景显示验收。公开初版的首次安装、开关和恢复说明见[背景组件](../components/codex-wallpaper/README.md)。
