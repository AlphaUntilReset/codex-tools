# 高清桌宠素材制作指南

本项目使用**一帧一张透明 PNG**，通过 `pack.json` 指定动作、顺序和时间。可以直接使用高清插画，不需要先压成像素画，也不要求把所有动作拼进固定网格图集。本文说明的是 Codex Tools 自备素材格式；它不是其他产品素材格式的说明。

最快的起点是一张你有权使用的透明 PNG。先让静态角色正常显示，再逐步添加眨眼、挥手和其他动作，最后考虑 16 方向视线。图片不会被上传，也不会自动生成缺少的动作。

## 1. 准备第一张高清图

推荐先选 **768×832** 或 **1536×1664** 画布。后者每边是前者的两倍，适合保留更细的线条与边缘；这两个尺寸只是制作建议，不是程序限制。

实际格式要求如下：

| 项目 | 要求 |
| --- | --- |
| 文件 | PNG；推荐 RGBA，也支持有透明信息的 LA / 调色板 PNG |
| 画布 | 宽和高分别为 1–4096 像素；所有动作帧和方向图的宽高必须完全相同 |
| 帧路径 | 相对 `pack.json`，用 `/` 分隔，例如 `idle/open.png`；不能指向包外或网络地址 |
| 最小动作 | 只需要 `animations.idle`，且至少一帧 |
| 动作帧数 | 每个动作 1–256 帧 |
| 单帧时间 | 16–60000 毫秒；省略 `durations_ms` 时，每帧 150 毫秒 |

画布可以不是正方形。程序按照源图宽高比绘制；画布中的透明留白也占空间，因此留白过大时，角色在窗口里会显得较小。把最终画布尺寸先定下来，后续全部帧沿用它。

制作时检查：

1. 背景是真透明，不是画出来的灰白棋盘格，也不是白底 JPEG 改名为 PNG。
2. 头顶、头发、脚尖和伸出的手没有被切掉；给挥手和跳跃留出空间。
3. 轮廓边缘没有不需要的白边或黑边。分别放到浅色、深色背景上检查。
4. 所有图属于你自己制作或已经获得适当使用许可的素材。代码的 MIT 许可不授予外部图片的使用权。

程序包用户启动 `CodexToolsPet.exe` 后选择图片。源码用户先按[根目录说明](../README.md#开发与验证)准备短路径 Python 环境，再从仓库根目录执行：

```powershell
$petPython = (node tools/python-env.cjs)
& $petPython components/desktop-pet/tools/asset_pack.py init --image "D:/MyArt/idle.png"
& $petPython components/desktop-pet/tools/asset_pack.py validate
```

程序把图片复制到 `components/desktop-pet/user-assets/pet/idle.png`，保留输入原图，并在同一目录创建下面的最小清单。素材始终与组件放在一起，不放入 Python 依赖环境：

```json
{
  "schema_version": 1,
  "animations": {
    "idle": {
      "frames": ["idle.png"],
      "durations_ms": [1500]
    }
  }
}
```

一帧保持多久都不会产生动作；这个最小包显示静态图片，其他基础动作暂时使用同一张图。`init` 遇到已有 `idle.png` 或 `pack.json` 会拒绝覆盖。尝试新版本时使用 `--output "D:/MyArt/pet-v2"`，不要删掉已验收的包来绕过保护。

## 2. 从眨眼与挥手开始

先准备两张待机图：`idle/open.png` 和 `idle/blink.png`。二者保持同一机位、头身比例、身体位置、衣服和照明，只改变眼睛。清单中的 `[1800, 120]` 表示睁眼停留 1.8 秒、闭眼停留 0.12 秒，随后循环。它不要求每一帧都用相同时间。

再制作 3–5 张挥手图，沿着一个清楚的小动作变化。起始和结束尽量接近自然站姿，方便返回待机。不要为了“更流畅”把手、脸和衣服每帧重新设计；一致性通常比帧数更多更重要。

避免抖动的关键是**固定画布中的站位**：

- 在绘图软件里放一条地面参考线，固定脚下接触点和身体中心线。
- 不要逐帧自动裁紧、独立放大或重新居中。相同画布尺寸只是第一步，画布内的角色位置也要一致。
- 用前一帧的半透明叠加图检查头部、肩膀和脚的位置。眨眼时身体不应平移；挥手时未参与动作的区域应保持稳定。
- 跳跃允许角色主动离开地面，但画布、相机和参考线保持固定；落地回到同一个站位。
- 左右跑动可以制作不同朝向。若使用镜像，要检查服装、文字和不对称饰物是否需要保留真实方向。

源图是高清图并不代表必须在桌面上显示很大。先用实际想要的桌面尺寸观看，检查线条是否清楚、动作幅度是否合适，再调整窗口大小。

## 3. 动作名称与播放规则

共有 9 个基础动作名称，其中只有 `idle` 必须提供。缺少其他基础动作时，程序使用待机帧；可选的 3 个额外动作不会凭空生成。

| 动作名称 | 场景 | 默认循环 |
| --- | --- | --- |
| `idle` | 空闲、任务结束后的基础姿势 | 是 |
| `running-right` | 向右拖动角色 | 是 |
| `running-left` | 向左拖动角色 | 是 |
| `waving` | 点击角色、手动挥手、已观察到任务完成后的提示 | 否 |
| `jumping` | 手动跳跃 | 否 |
| `failed` | 任务受阻 | 是 |
| `waiting` | 等待用户输入 | 是 |
| `running` | 工作中的基础动作 | 是 |
| `review` | 自然工作模式中的交替动作，也可手动播放 | 是 |
| `yawn` | 可选：待机时的生活动作 | 否 |
| `groom` | 可选：待机时的整理动作 | 否 |
| `thinking` | 可选：工作中的思考动作 | 否 |

`loop` 若填写，必须是 JSON 布尔值 `true` 或 `false`。手动触发的动作播一轮后返回当前任务状态；自然工作模式还会在片段之间加入停留，所以一轮自然行为的总时长不一定等于单个片段的帧时间之和。手动播放一个动作不会伪造或改变 Codex 任务状态。

## 4. 完整素材包示例

下面展示全部 12 个动作和可选方向图的写法。它是文件清单示例，不包含这些图片。先制作少量动作时，只留下 `idle` 和已经做好的动作；没有方向图时删除整个 `look` 字段。**不要留下指向不存在文件的条目。**

```json
{
  "schema_version": 1,
  "animations": {
    "idle": {
      "frames": ["idle/open.png", "idle/blink.png"],
      "durations_ms": [1800, 120],
      "loop": true
    },
    "running-right": {
      "frames": ["right/01.png", "right/02.png"],
      "durations_ms": [140, 140]
    },
    "running-left": {
      "frames": ["left/01.png", "left/02.png"],
      "durations_ms": [140, 140]
    },
    "waving": {
      "frames": ["wave/01.png", "wave/02.png", "wave/01.png"],
      "durations_ms": [180, 240, 180],
      "loop": false
    },
    "jumping": {
      "frames": ["jump/ground.png", "jump/air.png", "jump/ground.png"],
      "durations_ms": [120, 260, 180],
      "loop": false
    },
    "failed": {
      "frames": ["blocked/01.png", "blocked/02.png"],
      "durations_ms": [1000, 240]
    },
    "waiting": {
      "frames": ["wait/01.png", "wait/02.png"],
      "durations_ms": [1400, 180]
    },
    "running": {
      "frames": ["work/01.png", "work/02.png"],
      "durations_ms": [300, 300]
    },
    "review": {
      "frames": ["review/01.png", "review/02.png"],
      "durations_ms": [500, 300]
    },
    "yawn": {
      "frames": ["yawn/01.png", "yawn/02.png"],
      "durations_ms": [250, 700],
      "loop": false
    },
    "groom": {
      "frames": ["groom/01.png", "groom/02.png"],
      "durations_ms": [280, 280],
      "loop": false
    },
    "thinking": {
      "frames": ["think/01.png", "think/02.png"],
      "durations_ms": [350, 900],
      "loop": false
    }
  },
  "look": [
    "look/00.png", "look/01.png", "look/02.png", "look/03.png",
    "look/04.png", "look/05.png", "look/06.png", "look/07.png",
    "look/08.png", "look/09.png", "look/10.png", "look/11.png",
    "look/12.png", "look/13.png", "look/14.png", "look/15.png"
  ]
}
```

同一个 PNG 可以在列表中重复引用，例如挥手结束回到第一帧。`durations_ms` 的项数必须与 `frames` 一致；路径也可以使用中文，但建议采用简短、稳定的文件名，方便排查大小写和拼写问题。

## 5. 可选的 16 方向视线

`look` 是 16 张**完整、同尺寸的透明 PNG**，不是只放眼睛的小贴图。顺序从屏幕正上方开始，顺时针每次转 22.5°：

| 下标 | 方向 | 下标 | 方向 |
| --- | --- | --- | --- |
| 0 | 上，0° | 8 | 下，180° |
| 1 | 上偏右，22.5° | 9 | 下偏左，202.5° |
| 2 | 右上，45° | 10 | 左下，225° |
| 3 | 右偏上，67.5° | 11 | 左偏下，247.5° |
| 4 | 右，90° | 12 | 左，270° |
| 5 | 右偏下，112.5° | 13 | 左偏上，292.5° |
| 6 | 右下，135° | 14 | 左上，315° |
| 7 | 下偏右，157.5° | 15 | 上偏左，337.5° |

想做轻微眼神跟随，可以让身体与脸的位置完全相同，只在自己制作的各张图里改变视线。也可以制作头部跟随，但需保持颈部衔接与整体站位。程序不会替自备图片推算眼睛坐标，也不会自动补画中间方向。提供这 16 张图后，在托盘设置中开启鼠标跟随；省略 `look` 时，方向姿势统一使用待机首帧。

## 6. 使用 AI 辅助制作时

先确定一个你有权使用的角色设计和一张基准图，后续尽量以它作为编辑参考。可以从下面这段描述开始，并把方括号中的内容换成自己的要求：

> 为我拥有使用权的角色制作一张高清桌宠动作帧。透明 RGBA PNG，画布为 1536×1664，固定正面机位与全身构图，保持参考图中的脸、发型、服装、配色、线条和身体比例。角色脚底对齐同一地面参考线，四周留出动作空间。这次只改变：[闭眼眨眼 / 右手轻挥 / 轻微思考动作]。输出单独一帧，不做网格图集，不加文字、水印、地面或背景，不重新裁切或居中角色。

尺寸、透明通道和跨帧一致性仍要在导出后检查，提示词不能保证生成工具会完全遵守。发现脸部漂移、手指错误、服饰变化时，先修正这一帧，不要用模糊、强锐化或大量补帧掩盖问题。

## 7. 校验、试用与保存

每次编辑后，在仓库根目录运行：

```powershell
$petPython = (node tools/python-env.cjs)
& $petPython components/desktop-pet/tools/asset_pack.py validate "D:/MyArt/pet-v2/pack.json"
```

校验检查 PNG 编码、透明通道、画布、路径和帧时间，不评价动作是否自然。通过后退出桌宠，先备份当前 `user-assets/pet/`，再放入经过检查的新包并重新启动。保留基准图、分层制作文件、旧包与许可说明，方便回退和继续制作。

实际观看时依次检查：静止时边缘清晰、眨眼不带动头身平移、挥手切回待机不跳位、拖动时方向合理、跳跃回到原地、浅色和深色桌面上都没有意外边框。让动画连续播放几分钟，再判断频率是否过高。

角色图、PNG 帧、分层工程和已补齐素材的程序目录都应留在自己的电脑。公开分享素材包或截图前，单独确认图片的再分发许可；仓库忽略规则不会自动撤回过去已经上传的文件。完整格式与构建边界见 [PUBLIC-ASSETS.md](../components/desktop-pet/PUBLIC-ASSETS.md)。
