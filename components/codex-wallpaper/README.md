# Codex美化

[返回项目说明](../../README.md)。本组件是非官方的 Codex 桌面配套工具，提供主区域壁纸和侧栏背景。公开版本只分发源代码；使用者需提供自己有权使用的图片，不包含作者自用的角色原画、背景、截图或预览。

背景通过仅监听 `127.0.0.1` 的本机调试连接加载；不修改客户端安装包。主背景默认不透明度 0.15，侧栏 0.30。它不是通过官方插件市场注册的原生扩展；客户端界面结构变化后，CSS 选择器可能需要维护。

## 环境与素材

- Windows 10/11，已安装应用包版 Codex（`OpenAI.Codex`）。普通 ChatGPT 桌面应用不在此安装脚本的支持范围。
- Node.js 22 或以上、Windows PowerShell 5.1；构建图片样式需要 Python 3。
- 测试使用项目内的 Playwright 开发依赖。构建后的日常运行不需要 Playwright。
- 准备一张主背景 PNG、两张侧栏 JPEG。输入文件可保存在仓库外，文件名任意；程序读取原图，在本地构建目录生成运行资源。

侧栏模板按重复图 864×1084、结束图 864×842 的比例设计。建议先把自己的两张侧栏图准备为上述尺寸或相同比例；使用其他结束图比例时，同步调整 `源码/sidebar.template.css` 中两处 `842 / 864`。当前滤镜将近白底色统一为浅黄色，适合浅底插画；如需保留自己的原始背景色，可删除该模板中的 `filter: url("#codex-sidebar-bg-match")`。调色 SVG 只包含数值滤镜，没有角色图案或嵌入图片。

生成的 CSS 会内嵌你提供的图片，因此图片、CSS、运行配置和构建目录均应保留在本机。不要把生成的目录作为“纯代码”上传。构建不读取聊天记录，不下载图片，也不依赖作者的原图或私人预览。

本项目代码与文档采用 [MIT 许可](../../LICENSE)。上游 CSS 映射的版权及许可声明保留在 [`源码/ATTRIBUTION.txt`](源码/ATTRIBUTION.txt)。代码许可不授予任何外部图片的使用或再分发权。

## 构建与安装

在 `components/codex-wallpaper` 目录的 PowerShell 中运行：

```powershell
python 源码/prepare_images.py --background "D:\MyArt\background.png" --repeat "D:\MyArt\repeat.jpg" --ending "D:\MyArt\ending.jpg"
powershell.exe -NoProfile -ExecutionPolicy Bypass -File 源码/Install-FixedConfig.ps1 -AssetDirectory "build\own-images" -Plan
powershell.exe -NoProfile -ExecutionPolicy Bypass -File 源码/Install-FixedConfig.ps1 -AssetDirectory "build\own-images"
```

把示例路径换成自己的图片路径。第一条命令只创建本地资源，不安装或启动程序；`--output` 可以指定其他输出目录。第二条命令检查安装输入并列出计划，不写文件、注册表或快捷方式；第三条命令执行首次安装。未找到图片或格式不匹配会报错，不能用修改扩展名代替图片格式转换。

安装会在当前用户的 `%LOCALAPPDATA%\CodexSunFaded` 保存运行副本，在 `%USERPROFILE%\.codex-plugins` 保存独立登录保护脚本，添加本项目的登录启动项，并创建或更新桌面 `Codex.lnk`。桌面快捷方式直接保存 Windows 注册应用身份及本机调试参数，不经过 VBS 或 PowerShell；客户端更新安装目录后仍由 Windows 解析入口。登录项使用短 cmd 命令调用 cscript，脚本缺失或损坏时直接回退原生应用，避免 Windows Script Host 的找不到脚本弹窗。已有快捷方式会先备份。安装器遇到已有本项目启动项会停止，避免覆盖现有配置；它不是更新工具。

下载新源码不会自动替换已经安装的运行副本。安装器会拒绝覆盖已有配置；已有安装应先保留运行目录及其 `backup`，再按根目录说明维护，不删除备份或重复安装。公开版本不依赖作者的私人程序包或含原画的 Release。侧栏调色 SVG 在 `源码/sidebar.palette.svg` 维护。

默认不依赖或接管桌宠。如果已使用 CodexToolsPet 的 `--launch-codex` 登录项，而且希望由组合启动器负责启动两者，可在安装命令末尾加 `-IntegratePet`。该模式会验证并备份原设置，只禁用桌宠的重复登录入口，不修改桌宠设置文件。

组合启动标记同时保存在美化目录和独立的 `.codex-plugins` 目录。美化目录缺失或启动脚本超时时，登录兜底仍会恢复原生客户端并启动已接管自启的桌宠；未接管桌宠的安装不会额外启动它。恢复原生启动时清理两处标记。

桌宠 0.4.7.11 起，用户明确关闭自启会写入 `HKCU\Software\CodexToolsPet\LoginEnabled` 的 DWORD 0；组合登录主路径和全部兜底路径均跳过桌宠。DWORD 1、缺失或非法值继续按原有集成标记判断，手动启动不受影响。该选择不改背景开关或 Windows StartupApproved。

## 启动与恢复

安装器解析运行配置的真实文件路径，登录保护脚本使用该路径，防止 MSIX AppData 虚拟化导致外部进程无法访问。已有安装的路径可能包含应用包目录，排查时应读取实际保护脚本，不猜测路径。

配置位于运行目录的 `config.json`。背景不透明度、侧栏开关、端口和 Node 路径均在其中。配置或美化资源损坏时，启动器回退到 Windows 原生应用入口；外层观察程序约 20 秒后仍未收到完成信号，也会尝试原生入口。操作系统或客户端本身故障仍可能导致启动失败。

通过桌面图标启动时，如果客户端已运行，仍会调用正式应用入口唤回原有窗口，不终止或重新创建主进程。登录自启遇到已运行实例时则保留原窗口状态。

主启动器和应急入口从 Windows 当前注册的应用清单读取可执行文件，兼容更新后主程序改名，并识别同一 Codex 包族尚未退出的旧版本主进程；排除渲染子进程和命令行 Codex。桌面图标继续使用 Windows 注册应用身份。Windows 快捷方式内部可能缓存生成时的包版本信息，该缓存本身不证明图标已经失效；完全退出后的真实冷启动需要单独验证。

背景伴随进程通过 Windows WMI 独立创建，并检查没有继承客户端 MSIX 包身份。登录启动、手动启用和更新器均采用这种启动方式；现有组合入口启动桌宠时同样脱离客户端生命周期。客户端重载或调试端口暂时消失后，原伴随进程继续等待并自动重新连接。

客户端更新可能通过系统协议入口重新打开 Codex，省略本机调试参数。运行中的客户端无法追加这些参数；此时背景状态明确记录 `waiting_for_debug_port`，启动器记录 `restartRequired`，不能将进程存活当成背景已恢复。运行根目录 `修复背景.cmd` 后，从系统托盘选择完全退出 Codex，独立恢复程序会带本机配置的端口重新激活 Windows 注册应用。恢复程序最多等待 30 分钟，重复操作由互斥锁合并；禁用背景会取消等待。它不强制结束客户端，不修改原图片、透明度、登录项或官方安装包，也不创建常驻服务、计划任务或新自启。

- 根目录 `关闭自动背景.cmd`：禁用美化并清理当前主题节点。
- 根目录 `开启自动背景.cmd`：校验配置与资源后启用美化。
- 根目录 `应急原生启动.cmd`：不依赖配置解析或 Node，禁用美化并尝试打开原生客户端。
- 根目录 `恢复原启动方式.cmd`：恢复原生桌面入口和登录启动路径。仅处理本项目相关的注册表值；有有效备份时恢复原桌宠启动状态。
- 根目录 `修复背景.cmd`：准备独立恢复，等待用户完全退出客户端后，带背景连接参数自动重开。

上述入口由 `tools/control-wallpaper.ps1` 从独立保护脚本读取已解析的真实运行目录；不执行脚本文本，仅取字面量路径。这样从 Codex 外部双击时也能找到 MSIX 重定向后的安装。旧安装没有该路径时仍使用原名义 AppData 目录，应急入口保留原生应用兜底。

恢复步骤独立执行：桌面快捷方式不可写时，仍继续恢复登录项和原桌宠审批状态。若有步骤未完成，程序在尝试其余步骤后返回错误，细节写入运行目录的 `restore-status.json`，不把部分恢复报告为成功。

应急清理先给美化伴随进程退出时间，再核对命令行后终止仍未退出的本项目进程。清理端口来自客户端实际命令行，并核对监听端口所属进程；不要求配置文件完好。它不会主动结束客户端。

恢复原生启动后，仅开启背景开关不会重装登录启动入口。需要重新安装时，应先检查原生启动项及备份，再调整安装状态，避免重复入口。

## 验证与上传检查

以下命令使用合成测试输入和临时目录，不需要作者的图片。Python 命令在本组件目录执行，npm 命令在仓库根目录执行。

```powershell
python 源码/test_prepare_images.py
powershell.exe -NoProfile -ExecutionPolicy Bypass -File 源码/verify-startup-protection.ps1
```

图片构建测试验证缺失输入、格式错误、原文件保护、无私人目录时的构建和内嵌字节。它不代替图片解码和视觉验收。启动测试模拟安装、注册表和客户端操作，覆盖自带图片目录、只读计划、缺少资源时不留下半成品等情况，不启动真实客户端或更改日常启动项。

仓库根目录 `npm test` 提供其他启动和恢复测试。公开代码的测试通过不代表你的图片已经适合当前窗口尺寸；安装后应自行确认主背景、侧栏衔接、明暗模式和滚动显示。

上传前仍需查看暂存文件；`.gitignore` 不会自动移除过去已跟踪的图片或敏感文件。客户端更新后，需要实际确认背景状态为 `applied`，不能用伴随进程存在代替显示验收。
